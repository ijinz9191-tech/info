## 사용 원칙

1. 언어·프레임워크 버전, 런타임, 운영체제를 먼저 고정한다. 같은 API라도 버전에 따라 동작이 달라진다.
2. 이 위키의 설명은 설계와 진단의 출발점이다. 변경 가능성이 큰 API·지원 정책·보안 공지는 연결된 공식 문서를 재확인한다.
3. 오류를 다룰 때는 재현 입력, 기대 결과, 실제 결과, 오류 메시지, 실행 환경, 최근 변경을 함께 기록한다.
4. GitHub 저장소의 `main` 브랜치는 계속 바뀐다. 실제 구현을 인용할 때는 커밋 SHA와 파일 경로를 고정한다.
5. 인터넷이 끊긴 상태에서 출처를 갱신한 것으로 표시하지 않는다. 마지막 확인일과 확인 실패를 그대로 남긴다.

언어와 분야를 폭넓게 색인했지만 각 언어의 모든 API·버전·구현을 복제한 것은 아니다. [범위 장부](coverage.md)에 가이드와 색인의 깊이를 구분하고 [갱신 절차](maintenance.md)에 따라 부족한 주제를 계속 채운다.
