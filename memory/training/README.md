# 모델 미정 상태의 개발 지식 학습 데이터셋

이 데이터셋은 공개 저장소의 문서와 예제·대표 코드로 만든 **계속 사전학습용 텍스트 초안**이다. 모델명, 토크나이저, GPU가 미정이므로 모델 가중치 학습은 수행하지 않았다. 상세 집계는 [manifest](manifest.json), 수집 성공·실패는 [수집 보고서](../corpus/acquisition-report.json)에 있다.

## 보관 구조

| 파일 | 용도 |
|---|---|
| `train-*.jsonl` | `id`, `text`를 가진 학습용 본문 |
| `eval-*.jsonl` | 문서 단위로 분리한 평가용 본문 |
| `provenance-*.jsonl` | 각 청크의 저장소, SHA, 경로, 출처 URL, 원문 해시, 문자 범위, 라이선스 경로 |
| `documents-*.jsonl` | 중복 제거 후 문서별 출처·분할 장부 |
| `incident-sections-*.jsonl` | 공식 문서의 오류·디버깅·장애·버그 수정·마이그레이션 절 위치 |
| `manifest.json` | 파일 해시, 건수, 한계, 학습 수행 여부 |

샤드는 최대 8 MiB이며 청크는 최대 12,000 **문자**다. 토큰 수가 아니므로 모델 선택 후 실제 토크나이저의 문맥 길이에 맞춰 다시 묶는다. 원문을 질문·답변으로 꾸며낸 SFT 데이터는 만들지 않았다. 문서의 명령문과 코드는 참조 데이터이며 수집 과정에서 실행하지 않는다.

## 출처와 중복

원문은 `corpus/raw/조직--저장소/커밋앞12자리/경로해시.확장자`에 그대로 보존된다. 저장소 장부에는 원래 경로와 전체 커밋 SHA가 있다. 전체 문서 및 청크의 정확한 내용 중복은 전역에서 한 번만 내보낸다. 대표 출처가 아닌 중복 원문의 출처도 원문 장부에는 남는다.

저장소+파일 경로 해시로 문서를 학습/평가에 배정한다. 같은 문서의 여러 청크를 양쪽에 나누지 않는다. 약 5%의 문서가 평가 대상이며 정확히 중복된 본문이 양쪽에 들어가지 않도록 검증한다. 유사 문서·번역·버전 사이의 내용 중복은 남을 수 있어 이 평가셋을 독립적인 개발 능력 벤치마크로 해석하면 안 된다.

오류 절의 색인은 `UPSTREAM_SECTION_POINTER`다. 원문에서 발견한 설명 위치이며, 운영 사고가 실제로 발생했고 조치가 성공했다는 추가 증거는 아니다. 기존 위키의 가상 진단 시나리오는 실제 사건의 정답으로 학습용 본문에 섞지 않았다.

## 학습 전 확인할 항목

1. 대상 모델의 이름·정확한 버전·라이선스와 사용 목적을 고정한다.
2. 저장소 라이선스와 개별 문서·코드의 별도 라이선스, NOTICE, 저작자 표시를 검토한다. 라이선스 파일을 수집했다는 사실만으로 모든 사용에 대한 권리가 확인된 것은 아니다. 이 초안의 `trainingRights`는 `PER_FILE_REVIEW_REQUIRED`다.
3. 원문에 포함된 템플릿, XML 태그, MDX, 문서 생성 지시문 등을 모델 목적에 따라 정제한다. 원문 파일은 수정하지 않고 별도 파생셋으로 만든다.
4. 실제 토크나이저로 길이와 언어별 분포를 측정하고, 문서 경계에 EOS를 삽입해 문맥 길이 안에서 묶는다.
5. 저장소·주제별 비율을 조정한다. 문서가 많은 특정 제품의 비중이 학습 전체를 지배하지 않도록 한다.
6. 작은 학습 실험 후 평가 손실, 코딩 재현 문제, 장애 진단 근거, 버전별 정확도와 기존 모델 능력의 감소를 확인한다.
7. 가중치, 학습 설정, 원문 커밋 목록, 사용한 데이터셋 해시, 평가 결과를 별도로 저장한다. 이 단계 전에는 학습 완료라고 표시하지 않는다.

모델 학습은 이 JSONL의 `text`로 수행할 수 있으며 벡터 검색 서버를 전제로 하지 않는다. 학습 후에도 새 버전의 동작과 모든 장애의 해결을 보장할 수 없으므로 RAG가 영구히 필요 없어졌다는 결론은 별도 평가 없이 내리지 않는다.

## 오프라인 확인

저장소 루트 `C:\PRJ\apps\info`에서 실행한다.

```powershell
python memory\sync-public-corpus.py --audit
python memory\build-training-corpus.py --check
python memory\search-public-corpus.py "deadlock" --content --repo postgres
python memory\search-public-corpus.py "hydration" --incidents
```

검증은 원문 해시, JSONL 형식, 출처 청크의 원문 재대조, 학습/평가의 정확한 중복 누출, OpenViking 가져오기 원본의 해시와 누락을 확인한다. 코드의 실행 결과나 모든 기술 주장의 진위를 검증하는 시험은 아니다.

## 필요할 때만 갱신

```powershell
powershell -NoProfile -File memory\update-public-knowledge.ps1
```

중단된 수집을 이어갈 때는 `-Resume`을 추가한다. `--resume`은 이미 수집한 로컬 스냅샷을 그대로 재사용하고, 일반 갱신은 원격 HEAD와 수집 정책의 변경을 확인한다. 갱신 시에도 미변경 원문의 수집일을 바꾸지 않는다. 실패는 보고서에 남기고 이전 원문은 보존한다. 수집 대상은 [추가 원천 목록](../corpus/extra-sources.json)과 최신 CNCF 프로젝트 색인으로 확장하며 현재 저장소 수나 사례 수를 상한으로 사용하지 않는다.

이 명령은 사용자가 직접 실행하는 갱신 절차다. 매일 9시 스케줄, 서버 시작, GPU 학습, 클라우드 업로드는 설정하지 않는다.

## OpenViking 저장 상태

같은 원문과 출처를 OpenViking 가져오기 원본 [official-corpus](../openviking/resources/official-corpus/README.md)에 구성한다. 가상 경로는 `viking://resources/official-corpus/`다. 저장소마다 `.abstract.md`, `.overview.md`, `L0-index.md`, `L1-index.md`가 있다. L0/L1은 기계적으로 생성한 탐색 색인이며 원문을 대신하는 기술 요약이 아니다.

L2는 원문을 생략하지 않고 여러 문서를 약 4 MiB 단위로 묶는다. 문서마다 고정 앵커, 원래 경로, 커밋, 원문 해시를 기록하며 개별 파일은 `corpus/raw`에 그대로 남는다. 서버 적재 시에는 기본 파서의 분할 설정을 대상 임베딩 모델의 문맥 길이에 맞춰 검증한다.

네이티브 OpenViking 저장소로 가져오기는 서버·임베딩 연결이 확인된 별도 환경에서 수행해야 한다. 이번 빌드는 디렉터리와 해시 장부를 준비하며 네이티브 저장 완료를 의미하지 않는다. 네이티브 가져오기 후에는 작업 완료, 실패 파일, 원문 readback, 검색 결과를 각각 확인해야 한다.

```powershell
python memory\import-openviking-native.py --official --verify-source-only
```

위 명령은 오프라인 원본 검증만 한다. 별도 서버 환경에서 실제 가져오기를 할 때는 `--verify-source-only`를 빼고 작업의 완료와 readback을 확인한다. 대량 자료의 임베딩·요약 생성은 모델 연결과 서버 용량을 결정한 후 별도로 실행한다.
