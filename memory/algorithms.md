# 자료구조와 알고리즘 실전 지도

확인일: 2026-09-30. 알고리즘을 고를 때는 입력 크기 `n`, 정렬 여부, 중복, 값 범위, 업데이트 빈도, 메모리 제한, 정답의 정확성 요구를 먼저 적는다. 표의 복잡도는 일반적인 구현 기준이며 실제 비용은 언어·데이터·캐시·I/O에 좌우된다. [NIST DADS](https://xlinux.nist.gov/dads/)와 [MIT 알고리즘 강의 노트](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-fall-2011/pages/lecture-notes/)를 용어·분석의 기준으로 삼았다.

## 문제를 분류하는 순서

1. **정확한 입력·출력:** 빈 입력, 중복, 음수, 큰 수, 연결되지 않은 그래프, 동일한 최적값을 명시한다.
2. **상한:** `n=10^3`과 `n=10^7`은 허용 가능한 탐색 방식이 다르다. 시간·메모리 제한을 근거로 목표 복잡도를 정한다.
3. **형태:** 순서가 중요한가? 단조성이 있는가? 그래프인가? 부분문제의 답을 재사용할 수 있는가?
4. **불변식:** 루프가 끝날 때마다 무엇이 참인지 문장으로 쓴다. 예: 이진 탐색에서 정답 후보는 항상 `[lo, hi)`에 남는다.
5. **검증:** 작은 입력의 완전탐색과 비교하는 차등 테스트, 경계 사례, 성능 사례를 준비한다.

## 자료구조 선택표

| 요구 | 후보 | 전형적 비용 | 주의점 |
|---|---|---|---|
| 임의 위치 읽기 | 배열/벡터 | 인덱스 O(1) | 중간 삽입·삭제 O(n) |
| 키로 찾기 | 해시 맵/집합 | 평균 O(1) | 충돌·해시 품질·순서 보장 확인 |
| 정렬된 키와 범위 | 균형 트리 | O(log n) | 구현·상수 비용 |
| 최소/최대 반복 추출 | 힙/우선순위 큐 | 삽입·추출 O(log n) | 임의 원소 삭제는 별도 설계 |
| 앞에서부터 처리 | 큐/deque | 양 끝 O(1) | 배열 앞 삭제와 혼동 주의 |
| 연결성 병합 | Union-Find | 거의 상수의 분할상환 비용 | 일반적인 간선 삭제는 지원하지 않음 |
| 접두사 합 | prefix sum | 전처리 O(n), 질의 O(1) | 값이 바뀌면 재구축 필요 |
| 점 갱신+구간 질의 | Fenwick/segment tree | O(log n) | 구간 의미와 0/1 기반 인덱스 |

## 자주 쓰는 패턴

| 패턴 | 성립 조건 | 대표 작업 | 자주 틀리는 부분 |
|---|---|---|---|
| 이진 탐색 | 정렬 또는 단조 판정 | 경계값, 최소 가능 값 | 열린/닫힌 구간, 중간값 오버플로 |
| 두 포인터 | 이동에 따라 조건을 유지할 수 있음 | 정렬 배열 합, 병합 | 중복·포인터 교차 |
| 슬라이딩 윈도 | 연속 부분구간 | 최대/최소 길이, 빈도 | 음수가 있으면 합의 단조성 깨질 수 있음 |
| DFS/BFS | 그래프/격자 탐색 | 연결 요소, 최단 간선 수 | 방문 표시 시점, 순환 |
| Dijkstra | 간선 가중치가 음수가 아님 | 비음수 최단 경로 | 오래된 큐 항목 무시, 음수 간선 |
| 위상 정렬 | 방향 비순환 그래프 | 선행 작업 순서 | 순환 발견, 진입차수 갱신 |
| 동적 계획법 | 중복 부분문제·최적 부분구조 | 배낭, 편집 거리 | 상태 의미, 초기값, 전이 순서 |
| 그리디 | 교환 논증 등으로 지역 선택 증명 | 일부 정렬·스케줄링 | 직관만으로 최적성 주장 |
| 백트래킹 | 제약으로 탐색 가지치기 | 조합, 배치 | 상태 복구, 최악 지수 시간 |

### 이진 탐색의 안전한 틀

정수 범위 `[lo, hi)`에서 첫 번째 참을 찾는다고 하자. `predicate(x)`가 거짓에서 참으로 한 번만 바뀌어야 한다.

```text
while lo < hi:
    mid = lo + (hi - lo) // 2
    if predicate(mid): hi = mid
    else:              lo = mid + 1
return lo
```

반환값이 최초 참인지 검사하기 위해 `lo`가 범위 끝인 경우와 바로 앞 값이 거짓인 경우를 함께 테스트한다.

### BFS와 Dijkstra

- 모든 간선 비용이 같을 때 BFS는 각 정점의 최소 간선 수를 찾는다. 큐에 넣을 때 방문을 표시하면 중복 삽입을 줄인다.
- 가중치가 0 이상이면 우선순위 큐를 쓰는 Dijkstra를 고려한다. 꺼낸 거리와 현재 최선 거리가 다르면 오래된 항목을 버린다.
- 음수 간선이 있으면 Dijkstra 전제를 위반한다. Bellman-Ford 등 다른 방법을 검토하고 음수 순환을 정의한다.

### 동적 계획법

`dp[state]`가 무엇을 의미하는지 먼저 한 문장으로 쓴다. 예를 들어 `dp[i] = 처음 i개 항목까지 고려한 최적값`처럼 범위를 고정한다. 그다음 초기 상태, 전이, 계산 순서, 답 추출을 결정한다. 1차원으로 메모리를 줄일 때는 같은 라운드의 값을 재사용하지 않도록 갱신 방향을 검증한다.

## 계산과 테스트

- `O(n log n)` 정렬이 병목이라고 단정하기 전에 파싱·할당·I/O 비용을 측정한다.
- 평균 복잡도와 최악 복잡도를 구별한다. 해시 충돌, 퀵정렬 pivot, 재귀 깊이 같은 입력 특성을 검사한다.
- 정수 오버플로, 부동소수점 비교, Unicode 문자/바이트 길이, 시간대, 0/1 기반 인덱스는 알고리즘 자체와 별개로 실패를 만든다.
- 무작위 작은 입력에 대한 완전탐색 정답과 구현 결과를 비교한다. 실패 입력은 재현 가능하도록 seed를 보존한다.
