# 개발·운영 장애 대응 위키

확인일: 2026-09-30. 장애 상황의 우선순위는 **영향 확인 → 피해 완화 → 근거 보존 → 원인 검증 → 재발 방지**다. 확정되지 않은 원인을 사실처럼 기록하지 않는다. 이는 [Google SRE 사고 관리](https://sre.google/sre-book/managing-incidents/)와 [사후 분석](https://sre.google/sre-book/postmortem-culture/)의 기본 흐름을 범용 개발 환경에 맞게 요약한 것이다.

## 첫 10분의 기록

| 항목 | 적을 내용 |
|---|---|
| 시작과 탐지 | 시간대 포함 시각, 최초 경보/사용자 보고 |
| 영향 | 어떤 API·사용자·지역·데이터가 영향받는가; 모르는 범위는 미확인 |
| 정상 기준 | 이전 성공률·지연·처리량·큐 길이 |
| 변경 | 최근 배포, 설정, 스키마, 의존 서비스, 트래픽 변화 |
| 대응 | 담당자, 현재 완화 조치, 다음 점검 시각 |
| 근거 | 오류 예시, 요청 ID, trace ID, 대시보드 시간 범위 |

## 조사 순서

1. **증상 재현:** 최소 재현 요청과 예상/실제 결과를 고정한다. 재현이 안 되면 영향을 받는 조건을 비교한다.
2. **범위 절단:** 전체 요청인지 특정 경로·테넌트·버전·노드인지 나눈다. 의존성 상류와 하류의 첫 이상 시각을 비교한다.
3. **시간축:** 변경 시각, 에러율, p50/p95/p99 지연, 처리량, 포화도, 큐 길이를 같은 시간대로 놓는다.
4. **가설 검증:** 한 번에 하나의 가설을 세우고 그 가설을 반증할 수 있는 자료를 찾는다. 상관관계만으로 인과를 확정하지 않는다.
5. **완화:** 롤백·트래픽 우회·기능 제한·용량 조정 가운데 영향과 되돌리기 방법이 검증된 수단을 선택한다. 변경 전후 지표를 비교한다.
6. **복구 확인:** 오류율만 내려간 것으로 종료하지 않는다. 누락된 업무, 지연 이벤트, 중복 처리, 데이터 정합성까지 확인한다.

## 증상별 첫 분기

| 증상 | 우선 확인 | 흔한 오판 |
|---|---|---|
| 5xx 증가 | 에러 분류, 배포·의존성·타임아웃, 요청 ID | 모든 5xx를 같은 원인으로 묶음 |
| 지연 증가 | 구간별 trace, 큐·풀 포화, DB 계획, GC | 평균만 보고 꼬리 지연 무시 |
| 메모리 증가 | 힙/네이티브/캐시/연결 구분, 증가 기울기 | 무조건 메모리 누수로 단정 |
| CPU 증가 | 프로파일, 재시도 폭주, 락 경합, 입력 변화 | 높은 CPU를 곧바로 원인으로 판단 |
| 데이터 불일치 | 트랜잭션 경계, 중복/순서/재처리, 기준 원장 | 재처리 전에 현재 상태를 덮어씀 |
| 이벤트 지연 | 생산량, 소비량, 파티션별 lag, 독성 메시지 | 브로커 전체 문제로 일반화 |
| 연결 실패 | DNS → TLS → 라우팅 → 정책 → 서비스 준비 → 앱 | 네트워크 오류를 앱 오류와 혼동 |

## 관측 자료 연결

- **메트릭:** 범위와 추세를 찾는다. 집계된 값이라 한 요청의 인과 경로를 설명하지 못한다.
- **트레이스:** 요청이 거친 구간과 대기 위치를 본다. 샘플링과 누락된 span을 확인한다.
- **로그:** 구체적인 실패 맥락과 오류 코드를 본다. 구조화 필드, 요청 ID, trace ID를 연결한다.
- **프로파일:** CPU·메모리·락 등 코드 수준 비용을 본다. 부하와 동일한 조건에서 수집한다.

[OpenTelemetry](https://opentelemetry.io/docs/concepts/signals/)는 trace, metric, log를 별도 신호로 설명한다. 신호를 합칠 때는 같은 시각·서비스·요청 범위를 사용한다.

## 사후 분석 양식

```text
제목 / 날짜 / 영향 / 탐지 방법 / 복구 시각
타임라인: 관측된 사실과 실행된 조치
직접 원인 / 기여 조건 / 아직 확인 못 한 가설
영향이 커진 이유 / 탐지가 늦어진 이유
잘 작동한 대응 / 실패하거나 느린 대응
재발 방지 조치: 담당자, 기한, 검증 방법
참고 근거: 로그·트레이스·변경·테스트의 고정 링크
```

사람을 탓하는 설명보다 시스템 조건과 검증 가능한 조치를 남긴다. 권한·비밀값·개인정보가 포함된 원문은 공개 위키에 복사하지 않는다.
